## 1. 需求分析与接口梳理（已完成）

### 1.1 核心接口清单（MVP 范围）

| 业务 | Method | Path | 说明 |
|---|---|---|---|
| 登录 | POST | `/auth/sign-in` | 获取 token |
| 分类 | GET | `/categories` | 主目录 |
| 漫画列表 | GET | `/comics?page=&c=&s=` | 分区分页/排序 |
| 搜索 | POST | `/comics/advanced-search?page=` | 关键词搜索 |
| 漫画详情 | GET | `/comics/{comicId}` | 详情页数据 |
| 分话 | GET | `/comics/{comicId}/eps?page=` | 章节列表 |
| 阅读页（方式A） | GET | `/comics/{comicId}/order/{order}/pages?page=` | 按 comicId+order 拉取 |
| 阅读页（方式B） | GET | `/eps/{epsId}/pages?page=` | 按 epsId 拉取 |
| 推荐 | GET | `/comics/{comicId}/recommendation` | 详情页推荐 |
| 热搜词 | GET | `/keywords` | 搜索建议 |
| 喜欢切换 | POST | `/comics/{comicId}/like` | like/unlike toggle |
| 收藏切换 | POST | `/comics/{comicId}/favourite` | favourite/un_favourite toggle |
| 评论列表 | GET | `/comics/{comicId}/comments?page=` | 评论流 |
| 发表评论 | POST | `/comics/{comicId}/comments` | 受账号等级限制 |

### 1.2 关键请求头与签名规则

固定/约定请求头（按 README 与反编译代码交叉确认）：

- `api-key`
- `accept: application/vnd.picacomic.com.v1+json`
- `app-channel`
- `time`
- `nonce`
- `signature`
- `app-version`
- `app-uuid`
- `app-platform: android`
- `app-build-version`
- `authorization: <token>`（登录后接口）
- `image-quality`

签名相关：

1. 签名输入与 URL path、`time`、`nonce`、HTTP method、`api-key`、版本字段相关。
2. 反编译版本中会把 `Server-Time` 与本地时间差保存，用于后续请求时间修正。
3. 若签名字段或版本字段不一致，可能导致 4xx 或鉴权失败。

### 1.3 数据模型映射（MVP）

- Auth
  - `SignInRequest(email,password)`
  - `SignInResponse.data.token`
- Comic list
  - `ComicListResponse.data.comics.docs[]` + 分页字段（`total/limit/page/pages`）
- Comic detail
  - `ComicDetailResponse.data.comic`（标题、作者、分类、tags、统计、状态）
- Episode
  - `ComicEpisodeResponse.data.eps.docs[]`（`title/order`）
- Reader page
  - `ComicPagesResponse.data.pages.docs[].media.{fileServer,path}`
  - 图片地址拼装：`fileServer + "/static/" + path`

### 1.4 不稳定点与风险标记

- 风险R1：签名算法依赖字段较多，且历史版本可能改动。
- 风险R2：`time` 可能需要与服务端时间差对齐。
- 风险R3：`like/favourite` 为 toggle 语义，前端状态机要防抖与幂等处理。
- 风险R4：部分能力受账号等级限制（如评论）。
- 风险R5：不同路径都能拿阅读页（`/order/{order}` vs `/eps/{epsId}`），需选一条主链并保留回退。

## 2. 技术方案设计（已完成）

### 2.1 架构

- 推荐：`data / domain / ui` 三层 + MVVM + Repository。
- 建议模块：
  - `app`（入口与导航）
  - `core-network`（OkHttp3 + Retrofit + 拦截器）
  - `core-database`（Room）
  - `feature-auth / feature-home / feature-search / feature-detail / feature-reader`

### 2.2 网络层（OkHttp3）

拦截器链建议：

1. `HeaderInterceptor`：公共头注入。
2. `SignatureInterceptor`：按规则生成签名。
3. `AuthInterceptor`：注入 token。
4. `TimeSyncInterceptor`：读取响应 `Server-Time`，更新偏移量。
5. `LoggingInterceptor`：debug 打印（release 关闭）。

错误处理：

- 统一包装 `ApiResult.Success/Error`。
- 对 `401/403/429/5xx` 分级处理。
- 网络异常（超时、DNS、SSL）转领域错误码，便于 UI 统一提示。

### 2.3 序列化/并发/缓存

- 序列化：建议 Moshi（与 OkHttp/Retrofit 常见组合），或 Kotlinx Serialization（二选一即可）。
- 并发：Coroutine + Flow。
- 本地：Room + DataStore。
  - Room：阅读记录、收藏镜像、章节缓存索引。
  - DataStore：token、用户偏好（阅读方向、图片质量、预加载页数）。

### 2.4 图片与阅读性能

- 图片库：优先 Coil（Compose 生态友好），若 RecyclerView 方案可评估 Glide。
- 关键策略：
  - 临近页预加载（例如前后 2~3 页）。
  - 大图解码尺寸控制，避免 OOM。
  - 滑动中降级动画与占位策略。

### 2.5 Android 7~16 兼容点

- Android 7/8：TLS 与老设备网络差异、WebView/系统组件差异。
- Android 10+：分区存储，避免直接文件路径假设。
- Android 12+：前台服务/后台限制更严格。
- Android 13+：通知权限。
- Android 14~16：后台任务与隐私策略持续收紧，阅读下载需 WorkManager 化。

## 3. MD3 UI/UX 方案（已完成）

### 3.1 主题系统

- `MaterialTheme`（MD3）
  - `colorScheme`: Light/Dark 双套色板。
  - `typography`: 标题、正文、注释层级统一。
  - `shapes`: 卡片圆角、按钮圆角统一 token。
- 动态色策略：Android 12+ 启用 Dynamic Color；Android 7~11 使用静态色板。

### 3.2 页面信息架构

- 启动页（检查登录态/版本）
- 登录页
- 首页（推荐、分类入口）
- 分类页（分区/排序）
- 搜索页（关键词建议 + 结果）
- 详情页（封面、标签、章节、推荐、评论）
- 阅读器（沉浸式）
- 我的（收藏/历史/设置）

### 3.3 阅读器交互规范

- 浏览模式：
  - 默认纵向连续滚动。
  - 可切换左右翻页（后续增强）。
- 手势：单击显示/隐藏工具栏；双击缩放；长按弹操作。
- 沉浸式：状态栏与导航栏自动隐藏，边缘滑动恢复。
- 控制项：亮度、方向锁定、图片质量、预加载开关。
- 断网容错：单页失败可重试，整章失败支持回退章节列表。

### 3.4 MD3 组件落地建议

- 顶栏：`CenterAlignedTopAppBar` / `TopAppBar`
- 底部导航：`NavigationBar`
- 卡片列表：`Card`, `ElevatedCard`
- 操作按钮：`FilledButton`, `FilledTonalButton`, `FloatingActionButton`
- 筛选：`FilterChip`, `AssistChip`
- 反馈：`Snackbar`, `LinearProgressIndicator`, `PullToRefresh`（按版本支持）
